# 0001. Кросс-сборка ARM64 через QEMU

## Контекст

ТЗ требует сборку под три платформы: x86_64 + NVIDIA GPU, ARM64 / Jetson AGX Orin,
ARM64 / Jetson Orin Nano. Из ARM-платформ в наличии — только физические устройства
Orin, но они не подключены к CI как self-hosted runner.

## Рассматриваемые варианты

1. **Self-hosted runner на AGX и Nano.**
   Плюсы: нативная скорость, точное соответствие железу.
   Минусы: нужно физическое устройство с сетевым доступом к GitHub; для практики
   такой инфраструктуры нет.

2. **GitHub-hosted ARM runner.**
   Плюсы: не нужно своё железо.
   Минусы: доступен только на платных тарифах и в публичных репозиториях
   организаций; для личного репозитория — недоступен.

3. **QEMU через `docker/setup-qemu-action`.**
   Плюсы: работает из коробки в GitHub Actions, не требует железа.
   Минусы: сборка в 5–20 раз медленнее нативной; периодические segfault'ы
   при выполнении ARM-бинарей под эмуляцией.

## Решение

Используем **QEMU** (вариант 3). Это единственный вариант, работающий без
дополнительной инфраструктуры.

Обход проблем QEMU:
- **Segfault на `ldconfig`** — заменяем на no-op заглушку на этапе сборки
  базового образа.
- **Скорость** — компенсируется `type=registry,mode=max` для кеша слоёв.
  Второй и последующие прогоны собираются за минуты, а не десятки минут.

## Последствия

- Пайплайн работает на стандартных `ubuntu-latest` без доп. инфраструктуры.
- Все три платформы собираются одним workflow'ом.
- ARM-сборки медленные — до 90 минут на холодном кеше.
- Нет гарантии, что собранный под QEMU образ идентичен нативному на Orin.
  Для практики это приемлемо, для прода — нужен self-hosted runner.
- Если появится физический Orin — добавить в матрицу `runner: [self-hosted, arm64]`,
  QEMU при этом отключится автоматически (шаг `Set up QEMU` стоит под условием).
