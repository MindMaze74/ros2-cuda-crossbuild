## Статусы

| Статус | Что означает |
|---|---|
| **Proposed** | Решение обсуждается, ещё не принято |
| **Accepted** | Решение принято и действует |
| **Deprecated** | Решение больше не рекомендуется, но ещё применяется |
| **Superseded by NNNN** | Заменено новым решением (указан номер) |

## Что такое ADR

ADR — короткая записка на 1–2 страницы, которая фиксирует:

- **Контекст** — какая задача стояла и какие были ограничения.
- **Рассматриваемые варианты** — что ещё можно было сделать.
- **Решение** — что выбрали и почему.
- **Последствия** — плюсы, минусы, ограничения.

## Принципы

1. **ADR не переписываются задним числом.** Если решение меняется —
   создаётся новый ADR со статусом `Superseded by NNNN`. Старые остаются
   как история принятия решений.
2. **Каждое отклонение от первоначального решения фиксируется.** Даже если
   изменение кажется очевидным — оно должно быть задокументировано. Это
   защищает от «почему здесь так?» через полгода.
3. **ADR — это журнал решений, а не документация текущего состояния.**
   Текущее состояние видно из кода. ADR объясняет, **почему** код такой.

## Как добавить новый ADR

1. Скопируйте `0001-why-qemu.md` как шаблон.
2. Назовите файл `NNNN-краткое-название.md`, где `NNNN` — следующий номер
   (четыре цифры с ведущими нулями).
3. Заполните четыре секции: **Контекст** / **Варианты** / **Решение** /
   **Последствия**. Опционально — **Статус** и **Ссылки** в конце.
4. Добавьте строку в таблицу индекса выше.
5. Если новый ADR заменяет старый — поменяйте статус старого на
   `Superseded by NNNN` и добавьте ссылку на новый.
6. Закоммитьте вместе с PR, где применяется решение.

## Правила именования

- Имя файла: `NNNN-краткое-название.md` — латиница, дефисы, без пробелов.
- Заголовок внутри файла: `# NNNN. Человекочитаемое название`.
- Примеры: `0001-why-qemu.md`, `0004-why-cmake-binary-archive.md`.
